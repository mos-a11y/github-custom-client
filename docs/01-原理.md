# 01 · 原理：一个文件怎么撑起整个客户端

## 1.1 整体结构

```
┌─────────────────────────────────────────┐
│  <style>   CSS 变量 + 布局 + 组件样式      │
├─────────────────────────────────────────┤
│  <body>    极简骨架：#rail（侧栏）+ #app    │
├─────────────────────────────────────────┤
│  <script>                                │
│    ├─ CFG / AUTH      配置与登录态         │
│    ├─ gh() / gql()    API 封装（唯一出口）  │
│    ├─ esc() / mdToHtml()  工具            │
│    ├─ renderXxx()     各页面渲染函数        │
│    ├─ ROUTES          hash 路由表          │
│    └─ 启动：读令牌 → 画壳 → 跑路由          │
│  </script>                                │
└─────────────────────────────────────────┘
```

**只有两个真实 DOM 节点**：侧栏和主区。
每个页面就是往 `document.getElementById('app').innerHTML` 里塞一段字符串。

这就是全部。没有虚拟 DOM，没有 diff，没有状态树。

## 1.2 主题：靠 CSS 变量

```css
:root{
  --bg:#0d1117; --bg-sub:#161b22; --fg:#e6edf3;
  --fg-muted:#8b949e; --border:#30363d;
  --accent:#58a6ff; --green:#3fb950; --red:#f85149;
}
```

**换主题 = 改这几个变量。** 所有组件都引用变量，不写死颜色。
想加一套浅色主题，只要：

```js
document.documentElement.style.setProperty('--bg', '#ffffff');
// ... 改完一组即可
```

## 1.3 路由：hash 驱动

```js
var ROUTES = [
  [/^#\/repo\/([^/]+)\/([^/]+)$/,  renderRepo],   // #/repo/owner/name
  [/^#\/user\/([^/]+)$/,          renderUser],   // #/user/xxx
  [/^#\/$/,                       renderHome]
];

function route(){
  var h = location.hash || '#/';
  for (var i = 0; i < ROUTES.length; i++){
    var m = h.match(ROUTES[i][0]);
    if (m) return ROUTES[i][1].apply(null, m.slice(1));
  }
  renderHome();
}
window.addEventListener('hashchange', route);
```

**为什么用 hash 而不是 pathname？**
因为 `file://` 和静态托管都没有后端重写规则，
`https://x.com/repo/a/b` 会 404，而 `https://x.com/#/repo/a/b` 不会。

**跳转就写 `href="#/repo/o/r"`**，浏览器自己改 hash，路由自动跑。

## 1.4 渲染：字符串拼接 + innerHTML

```js
function renderRepo(owner, name){
  app.innerHTML = '<div class="spinner"></div>';   // 先占位
  gh('/repos/' + owner + '/' + name).then(function(r){
    app.innerHTML = '<h1>' + esc(r.name) + '</h1>' + ...;
  });
}
```

### 两条铁律

**① 所有用户输入必须 `esc()`**

```js
function esc(s){
  return String(s == null ? '' : s)
    .replace(/&/g,'&amp;').replace(/</g,'&lt;')
    .replace(/>/g,'&gt;').replace(/"/g,'&quot;');
}
```

仓库名、Issue 正文都可能含 `<script>`。不转义 = XSS。

**② 先占位，再填充**

异步有延迟，不先放个 spinner，用户会以为"点了没反应"。

## 1.5 事件绑定：为什么要用委托

**这是最容易踩的坑。**

```js
// ❌ 错：列表重绘后监听全丢
list.querySelectorAll('.btn').forEach(b => b.onclick = handler);

// ✅ 对：挂在 document 上，重绘多少次都有效
document.addEventListener('click', function(e){
  var b = e.target;
  while (b && b !== document){
    if (String(b.className).indexOf('issRepBtn') >= 0){ /* 处理 */ break; }
    b = b.parentNode;
  }
});
```

**原因**：`innerHTML = ...` 会销毁旧节点、创建新节点。
绑在旧节点上的 `onclick` 随之消失。
而 `document` 本身不被替换，委托永远有效。

> 向上遍历而不用 `closest()`，是为了兼容老浏览器。

## 1.6 加载状态的三个层次

| 场景 | 做法 |
|---|---|
| 首次进入 | `app.innerHTML = '<div class="spinner"></div>'` |
| 局部刷新 | 按钮 `disabled = true` + 文案改成"加载中…" |
| 后台补充 | 不阻塞，拿到再 `insertAdjacentHTML` 补进去 |

第三种最舒服：主内容先出来，次要信息（审核状态、统计数据）慢慢补。

## 1.7 分页

GitHub 用 `Link` 响应头分页。简单场景直接 `per_page` 拉够：

```js
gh('/user/repos?per_page=100&sort=updated');
```

`per_page` 最大 100。要更多就翻页：

```js
gh('/user/repos?per_page=100&page=2');
```

## 1.8 条件请求：省额度

```js
gh('/repos/o/r/contents/README.md', {
  headers: { 'If-None-Match': etag }
});
```

没变化返回 **304**，不消耗配额。轮询场景必用。

## 1.9 文件读写

**读**：返回 base64，要解码。

```js
gh('/repos/o/r/contents/path/to/file.md').then(f => {
  const text = decodeURIComponent(escape(atob(f.content.replace(/\s/g,''))));
});
```

> 必须用这个"转义再解码"的两步写法，否则中文乱码。
> 现代浏览器也可以用 `TextDecoder`：
> ```js
> const bin = Uint8Array.from(atob(b64), c => c.charCodeAt(0));
> const text = new TextDecoder('utf-8').decode(bin);
> ```

**写**：**必须带 `sha`**，否则 422。

```js
gh('/repos/o/r/contents/file.md', {
  method: 'PUT',
  body: JSON.stringify({
    message: 'update file',
    content: btoa(unescape(encodeURIComponent(newText))),
    sha: f.sha          // ← 从 GET 拿到的，防覆盖冲突
  })
});
```

## 1.10 为什么不用框架

| 需求 | 框架 | 本方案 |
|---|---|---|
| 首屏 | 要先下 100KB+ 运行时 | 0 |
| 构建 | webpack / vite | 无 |
| 部署 | 打包上传 | 传一个文件 |
| 离线 | 需配置 | 天然支持 |

代价：手动管理 DOM 更新，列表重绘要记得用事件委托。
**对这个规模（几千行）来说，这笔交易是划算的。**
